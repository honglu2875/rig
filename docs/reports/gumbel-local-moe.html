Almost no MoE update.

Fresh Gumbel routes and a statistics-normalized inner loop revisit every routed block between ordinary AdamW updates. Two local steps nevertheless match the exact baseline to five decimal places in the three-seed mean. The most useful result is not today’s wall-clock cost, but the mechanism traces: the router hardens while the local parameter move remains microscopic.

The experiment began with a deliberately spare idea. An MoE layer owns much more stored capacity than it activates for any token. If ordinary training only follows the winning route, perhaps a few additional, perturbed routes can explore that capacity without inventing a second optimizer or a collection of routing rules.

The implementation does exactly that. One ordinary forward/backward captures each routed block's frozen input, residual input, output, and output cotangent. Every local step then revisits only the MoE sublayers, draws fresh standard Gumbel noise for hard top-2 selection, keeps clean gate weights on those selected experts, and minimizes one activation-normalized objective with stateless SGD.

That simplicity made the present result unusually legible. The intervention changes routing statistics, but its parameter-space contribution is so small that the combined update remains essentially the ordinary AdamW update. That—not the current kernel efficiency—is why this exact realization is not ready to carry forward.

short answerThe idea remains open; this update is too small.

K=2 changes mean validation by +0.000021 nats, and the first combined update norm barely moves from baseline. Preserve the mechanism and redesign its normalization before judging the idea at equal FLOPs on larger models.

The implemented algorithm

One global backward supplies all local targets; the inner loop recomputes only routed MLPs.

The implementation is deliberately between ordinary training and a full inner optimization of the network. It does not run the transformer forward and backward K additional times. Instead, the ordinary outer pass exposes just enough information to construct an independent local problem for every MoE block. Attention, normalization, embeddings, the loss head, and propagation between blocks are frozen during the local loop.

Logical order of one compiled training step

JAX compiles this as one executable, but the data dependencies are the following.

  1. Outer forward and backward.Evaluate the normal LM loss plus the 0.01 Switch-style router auxiliary loss at parameters θt. Save, for every block l, the normalized MoE input nl, residual input rl, complete residual output yl, and output cotangent gl = ∂L/∂yl.
  2. Ordinary AdamW update.Update the global first and second moments once and form θ̄ with the normal CompleteP learning-rate, epsilon, and decay multipliers. The local loop never changes Adam's m or v and never applies another decay step.
  3. Update three scalar statistics per block.From the frozen outer tensors, update bias-corrected EMAs of mean(rl²), mean(yl²), and mean(gl²), using the same effective β₂ as the outer AdamW. These are scale estimates, not optimizer moments for parameters.
  4. Take K local routed updates.Starting from the MoE leaves of θ̄, repeatedly sample new hard routes, evaluate all block-local objectives on the cached tensors, and apply stateless SGD only to router and expert weights/biases. Replace those leaves in θ̄ to obtain θt+1.

The output cotangents come from a zero-perturbation trick.

During the outer forward pass, the code inserts an identically zero tensor ul after each complete MoE residual sublayer and differentiates the loss with respect to both θ and all ul. Because adding zero does not change the forward computation, ∂L/∂ul is exactly the cotangent of that block output. This obtains every gl in the ordinary reverse traversal; there is no second full-model backward and no hook-driven host round trip.

Gumbel changes the discrete assignment, not the gate amplitude.

The outer pass remains the deterministic clean top-2 path from reference_moe; Gumbel noise exists only in the local loop. For token m and expert e, the current local router produces a clean logit zm,e. Each inner step draws independent standard Gumbels γm,e—split by layer and folded with the data-shard index—and chooses

Sm = Top2e(zm,e + γm,e),    πm,e = softmax(zm,e for e ∈ Sm).

This is hard Gumbel top-k, not Gumbel-softmax and not a straight-through relaxation. Noise determines which two experts execute; their mixture weights are recomputed from the clean selected logits. That isolates assignment exploration from amplitude noise. Assignments are stably sorted by expert, executed dropless through grouped matmuls, weighted by π, and scatter-added back to token order. There is no capacity factor and no dropped token.

The distinction also defines the router gradient. Top-k indices are piecewise constant, so there is no gradient estimator through “which expert won.” The router receives gradients only through the clean softmax weights of the experts sampled on that step; selected experts receive the ordinary pathwise gradient. The outer pass remains responsible for the explicit load-balancing loss.

The local objective is an output-space target and restraint in one square.

With the current post-AdamW MoE parameters φ, a sampled route produces a candidate residual output ỹl from the frozen nl and rl. Define δl = ỹl − yl. The per-layer scale is sl² = ½(EMA[rl²] + EMA[yl²]), and ql² = EMA[gl²]. The optimized objective is

J(φ) = Σl ½ · mean((δl / sl + gl / ql)²).

Expanding the square makes the intended geometry clear. The δ² term penalizes output displacement in units of the block's activation scale. The δ·g cross term is the first-order change in the global loss and prefers motion against the cached output gradient. The g² term is constant with respect to φ. In the unconstrained output space, the minimum would be δl = −(sl/ql)gl; the routed expert parameterization decides how closely the block can realize that target. Because φ starts after the outer AdamW update while yl was cached before it, the first δ also includes the outer update's change in that block; later local steps retain the same reference output.

# after one normal forward/backward and one AdamW update
φ ← MoE_leaves(θ̄)
for j in 1 … K:
    for every block l:                 # frozen n_l, r_l, y_l, g_l
        S_l ← top2(router_φ(n_l) + fresh_gumbel)
        π_l ← softmax(clean_logits_φ(n_l)[S_l])
        ỹ_l ← r_l + residual_scale · MoE_φ(n_l, S_l, π_l)
        J_l ← ½ mean(((ỹ_l − y_l)/s_l + g_l/q_l)²)
    φ ← φ − η_t · CompleteP_multiplier · ∇_φ Σ_l J_l
θ[t+1] ← replace_MoE_leaves(θ̄, φ)

Frozen through all K steps

Normalized inputs, residual inputs, reference outputs, output cotangents, and corrected scale EMAs. Candidate block outputs do not feed the next block, so all local problems share one outer linearization.

Changes on every local step

Router/expert parameters and the Gumbel assignments. A fresh route is drawn for every layer, token, and data shard; the next inner step sees the preceding local parameter update.

Parameters that can move

router_w and every expert's up/down weights and biases. Attention, RMSNorm scales, embeddings, unembedding, and all Adam states are excluded.

Deliberately absent knobs

No temperature, trust radius, separate local LR, local momentum, gradient clipping, local weight decay, capacity factor, or local router auxiliary loss. ηt and the CompleteP tensor multipliers are reused; only the scale EMAs and PRNG persist across outer steps.

K=0 skips activation/cotangent capture and the entire local path, which is why it is an exact implementation baseline rather than “K local steps with a zero multiplier.”

The endpoint

The primary comparison is not merely “not significant”; it has no stable direction.

The main arm is K=2 against K=0, paired across three seeds. Seed 1350 improves by 0.00270 nats, seed 1388 improves by 0.00213, and seed 1369 worsens by 0.00489. Those movements cancel to a mean penalty of 0.000021 nats. The single-seed step-count probes are less kind: K=1 and K=4 both finish worse than the matching seed-1350 baseline.

A three-seed null should not be sold as a precise zero. The paired sample SD is 0.00423 and the two-sided 95% Student-t interval is roughly [-0.0105, +0.0105]. But the mechanism decision does not depend on a tight interval: there is no monotone response to more local steps, no persistent training-curve separation, and the measured local contribution is too small to represent a serious alternative update.

Compute accounting

Today’s wall-clock multiplier is an engineering measurement, not the algorithmic verdict.

The fixed-model experiment intentionally gives K>0 more total compute. The traced FLOP multiplier is smaller than the local-step count because attention, embeddings, dense block components, and the one outer update are unchanged: each inner step revisits only the routed MLPs. Wall time is less favorable at this 125M scale. K=2 is a 1.34× FLOP run but a 1.97× training-time run, so the current local kernel path realizes fewer FLOPs per second than the full outer step.

That gap matters for budgeting this prototype, but it is not the research criterion. If a redesigned local update moves the loss–compute frontier at matched total FLOPs, the method is worthwhile even when its first implementation is slower per FLOP. Model width, active parameter count, token budget, and the number of local steps can be adjusted to construct an algorithmically equi-FLOP comparison; kernel fusion and routing layout can be optimized afterwards.

The intended destination is also larger models, not this 125M prototype. Larger expert matrices raise arithmetic intensity and make grouped expert forward/backward work progressively more compute-bound; fixed costs such as sorting, dispatch, and launches should occupy a smaller fraction of the step. The present wall/FLOP gap therefore should not be extrapolated as the asymptotic systems cost. It identifies optimization work, not a fundamental penalty.

For completeness, a common-compute cross-section can be read from these runs. When seed 1350 reaches the baseline's final cumulative FLOPs, K=0 has seen 617M tokens, while K=1/2/4 have seen 527M, 459M, and 365M. Their 100-step-smoothed training losses are 3.5827, 3.6420, 3.6752, and 3.8100. This says the current tiny local update does not compensate for the token updates it displaces under the unchanged schedule.

This is not the algorithmically equi-FLOP experiment we ultimately care about. The arms share a model size, token horizon, and token-indexed LR schedule; none was resized or retuned for its total FLOPs. A future test should first make the local update numerically consequential, then compare appropriately sized/scheduled models at the same traced training compute. Wall time should remain a separate systems axis.
The router response

Gumbel perturbation does not keep the clean router exploratory.

The last 200 steps show a modest improvement in the auxiliary balance statistic: the mean balance loss moves from 1.0451 to 1.0372, and the idlest assignment share rises from 0.0419 to 0.0525. Those numbers might look like the intended exploration if read alone.

The confidence statistics point the other way. Clean routing entropy falls by 0.0203 nats in every paired seed, while clean logit RMS rises by 0.0306. The gate's top-1 weight also increases slightly. A coherent explanation is that repeated hard perturbation rewards a router for building larger clean margins that survive the noise. The intervention visits alternative routes, but the learned deterministic router becomes more—not less—decisive.

Hard top-k also limits what the local gradient can express. It can update the experts that happened to be selected and the clean mixture weights attached to them. It cannot differentiate through the identity of the winner, so it cannot directly teach an unselected expert that it should have received the token. Gumbel changes the discrete path; it does not make that path choice differentiable.

The dominant mechanism

The local objective is mathematically normalized, but its parameter update is numerically negligible.

The local loss combines a normalized output displacement and normalized cached output gradient:

0.5 · mean((Δoutput / activation_RMS + output_gradient / gradient_RMS)²)

This is attractive because the cross term supplies a descent direction while the squared displacement acts like an activation-scaled restraint. Yet “dimensionless objective” does not imply “well-scaled parameter update.” The mean is taken over approximately 16 × 8192 × 640 ≈ 84 million activation values per block. Its gradient is then fed to raw SGD at a learning rate tuned for AdamW-preconditioned gradients.

The diagnostic consequence is stark. On the first outer step—where all arms begin from identical parameters and data—the mean block actual-update L2 norm exceeds K=0 by only a few parts per million.

The local loss and activation ratio also show no monotone improvement with more inner steps. That leaves a simple interpretation: these runs spend extra forward/backward compute, but the local vector is too small to compete with the one ordinary AdamW update. The router response is real; the parameter-space exploration is barely there.

What remains worth testing

Normalize the intervention by what it must compete with.

This study should not motivate a larger reseed of the same update rule. Its useful follow-up is a change of normalization, not another discretionary coefficient. Cache the ordinary MoE parameter delta—or its predicted output displacement—and scale the local delta to a fixed relationship with that observed quantity. The target can be one outer-update RMS, or one outer-update-induced output RMS. Either choice makes the intervention adaptive to width, depth, layer scale, and training time without introducing a hand-tuned “local LR multiplier.”

The next mechanism run should log the local and outer update norms separately before they are summed, plus their cosine and predicted output-displacement RMS. Once the local direction is large enough to test, the scientific follow-up is a larger-tier, matched-total-FLOP comparison with model size or token budget adjusted as necessary. That separates three questions cleanly: whether the direction helps, whether it helps per FLOP, and how efficiently the current kernels realize those FLOPs.

Evidence boundary

  • The primary comparison has three seeds at one 125M, 8k, 5-TPP setting. K=1 and K=4 are single-seed probes.
  • Every arm uses the same token-indexed LR schedule. The common-FLOP cross-section is diagnostic, not a schedule-retuned equi-FLOP experiment.
  • The measured wall multiplier is specific to replicated experts and relatively small grouped matmuls at 125M. Larger tiers are expected to move the local work toward compute-bound execution.
  • Per-expert router loads are complete. Parameter/gradient/update diagnostics were requested at block scope only, so expert-specific update attribution is unavailable in this study.
  • The conclusion rejects the tested hard-Gumbel, normalized-objective, raw-SGD realization. It does not reject all extra-compute MoE exploration.

Working conclusion

Keep the algorithmic idea; replace this local update before scaling the study. Hard Gumbel routing appears to sharpen the clean router, and the actual local parameter move is measured in parts per million of update-norm ratio. The current cost table is useful systems evidence, but it is not a rejection criterion: after the normalization is repaired, the real test is loss at matched total FLOPs on larger models, with size and kernels treated as adjustable implementation choices.
