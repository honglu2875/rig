Leave-one-occurrence-out infinigram distillation

A reconstruction specification and comparison record for a sampled suffix-array teacher on FineWeb. The experimental implementation is deliberately not merged; this document defines the change closely enough to rebuild it on top of the dense reference trainer.

Decision. Do not land the infinigram trainer, ngram patches, or sampled-output kernel. The only development point to reach its paired dense endpoint was K=1, b=0.10, by -0.000524 nats; that is only 0.042 times the historical three-seed dense sample SD. Scope and evidence boundary

The question was whether an on-disk infinigram could act as a useful training target without transferring a full vocabulary distribution. The work proceeded adaptively, but each individual grid was frozen before its cells ran.

The archive contains those 23 new scientific runs plus the exact 125M dense seed-1337 run used throughout, copied from its earlier sealed study. All treatment grids and the 500M pair have one seed. The three historical 125M dense seeds quantify ordinary endpoint scale only; they do not form a paired treatment variance estimate or a confidence interval. There is no corresponding 500M seed cohort, so the hero result has no across-seed uncertainty estimate.

Validation was a single deterministic endpoint evaluation on 1,048,576 held-out FineWeb tokens. There were no intermediate validation probes. Training losses across arms are not directly comparable because treatment logs contain the mixed objective while dense logs contain ground-truth cross-entropy. Claims about early or late validation separation cannot be made from these runs.

Objective and estimator

For position i, let ci be the model-visible context, yi the observed continuation, hi the final normalized student state, Ev output row v, and ℓiv=hiTEv. The semantic vocabulary has V=50,257 entries. The teacher is the adjusted suffix distribution qiLOO. Draw K independent targets with replacement:

tij ~ qiLOO(· | ci), j=1,…,K. Li = (a+b) log Σv<V exp ℓiv − a ℓi,yᵢ − (b/K) Σj=1..K ℓi,tᵢⱼ, a ≥ 0, b ≥ 0, a+b = 1.

The trainer rejects coefficients that do not sum to one within absolute tolerance 10-12. When only --infinigram-weight b is supplied it sets a=1-b. Conditional on the context and adjusted counts,

E[Li] = a CE(δyᵢ, pθ) + b CE(qiLOO, pθ), Var[(1/K) Σj −log pθ(tij)] = Var[−log pθ(t)] / K.

Thus K changes Monte Carlo variance, not the expected teacher objective. The teacher sample is a stopped, host-produced integer target: no gradient is taken through the suffix search, counts, or draw. Because a+b=1, the log-normalizer coefficient and broad softmax gradient scale match ordinary cross-entropy.

Exact adjustment

For a candidate suffix s of length m, define cm(v) as the number of indexed occurrences of s that have successor v. A suffix occurrence at the final token of an index shard has no successor and is excluded. Let Am=Σvcm(v), Om=cm(yi), and em=1[Om>0]. The training teacher is

qi,mLOO(v) = [cm(v) − em 1(v=yi)] / (Am−em).

This removes one matching occurrence rather than deleting the whole ground-truth token type. If the queried sequence is not present in the index and Om=0, nothing is subtracted. If Am−em=0, the query backs off. Length zero is the final corpus-frequency fallback; an empty adjusted corpus is a hard error.

for each batch row r:
    split [0, T) into segments at every x[r,t] == 50256
    # the old segment ends before EOT; the new segment begins with EOT
    for each segment [begin, end), in a 30-thread host pool:
        previous_length = 0
        for t in range(begin, end):
            cap = t - begin + 1
            if max_context > 0: cap = min(cap, max_context)
            m = min(previous_length + 1, cap)
            loop:
                suffix = x[r, t+1-m : t+1]
                ranges = suffix_array_find_in_every_shard(suffix)
                A = count_occurrences_with_a_successor(ranges, m)
                O = count_matches(suffix + [y[r,t]], restricted_to=ranges)
                e = 1 if O > 0 else 0
                if A > e: break
                if m == 0: fail("empty leave-one-out corpus")
                m -= 1

            state = batch_seed XOR (0x9e3779b97f4a7c15 * (r*T+t+1))
            repeat K times:
                loop:
                    occurrence = splitmix64(state) modulo A
                    sampled = successor_of_occurrence(occurrence)
                    if e == 0 or sampled != y[r,t]: accept
                    elif splitmix64(state) modulo O != 0: accept
                    # otherwise reject and redraw
                targets[r,t,j] = sampled
            suffix_length[r,t] = m
            prompt_count[r,t] = A-e
            truth_count[r,t] = O-e
            previous_length = m

Starting from previous_length+1 is exact: an adjacent suffix match can grow by at most one, and if a longer prior suffix became empty only because its sole observed continuation was removed, its one-token extension cannot acquire a second occurrence. Uniform occurrence sampling followed by rejection of a sampled ground-truth continuation with probability 1/O gives accepted aggregate mass O-1 for that token and unchanged mass for every other token, exactly implementing the equation above.

Sampling and determinism

The Python trainer computes one unsigned 64-bit seed for each rank-local optimizer batch. Arithmetic wraps modulo 264:

z = uint64(run_seed)
z ^= uint64(step)          * 0xD1B54A32D192ED03
z ^= uint64(process_index) * 0x94D049BB133111EB
z += 0x9E3779B97F4A7C15
z = (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9
z = (z ^ (z >> 27)) * 0x94D049BB133111EB
batch_seed = z ^ (z >> 31)

The C++ engine xors this with the position-specific golden-ratio multiple shown in the query pseudocode, then uses the standard SplitMix64 state transition for each occurrence draw and possible rejection draw. Each position owns its state, so thread scheduling cannot change samples. Within one position, K samples are sequential draws with replacement. Therefore fixed-seed K=16 targets are byte-for-byte prefixes of K=32 and K=64 targets. Changing b or the student learning rate does not change teacher targets because the model is never consulted by the query.

Data order itself is the dense trainer's deterministic shuffled_epochs stream. Four JAX processes construct the same global permutation and take disjoint rank slices. The 125M horizon consumes 0.078129 of the available training tokens. The 500M horizon consumes about 1.2724 corpus epochs and begins a newly seeded shuffled epoch after exhausting the first; leave-one-out still removes one occurrence from the fixed teacher corpus at each visit.

Student loss and custom gradient

The dense model has untied input and output embeddings. The historical function name contains “tied,” but the modified primitive receives the actual output table E of shape [50,304,D]. Rows 50,257–50,303 exist only for storage alignment and are assigned neither probability nor gradient. The loss uses a vocabulary tile of 2,048, BF16 matrix operands, and FP32 dot accumulation, online log-sum-exp, probabilities, gradient accumulators, and final mean.

Forward pass

  1. Flatten h from [B,T,D] to [N,D]. Pad E to a whole number of 2,048-row tiles.
  2. Walk every vocabulary tile once. Compute [N,2,048] logits and an online FP32 maximum/exponential sum, masking non-semantic rows to negative infinity.
  3. Gather E[y] and compute the primary target logit with an FP32-accumulating dot.
  4. Loop over the static sample dimension. At each j, gather only E[tj] with shape [N,D], dot with h, and add to one [N] accumulator. Divide by K.
  5. Return the per-position equation above and mean in FP32.

This does not materialize [N,V] logits, a dense teacher vector, or [N,K,D]. The forward teacher work is K gathered row dots, O(NKD), while the shared normalizer remains one O(NVD) tiled projection.

Backward pass

Let gi be the upstream cotangent after the final mean. The exact logit derivative is

∂L/∂ℓiv = gi[(a+b)piv − a·1(v=yi) − (b/K)Σj1(v=tij)] .

The custom VJP recomputes one vocabulary tile at a time. Each tile contributes the softmax term and primary correction to ∂h and the dense output-table gradient. For K=1 it also compares the one teacher ID inside that tile, preserving the original dual-target path exactly. For K>1 it omits teacher-ID comparisons from the vocabulary loop, then applies the sparse correction in chunks of eight samples:

Δ(∂hi) = −gi(b/K) ΣjEtᵢⱼ Δ(∂Etᵢⱼ) += −gi(b/K) hi.

Targets are clipped only to make invalid-gather behavior defined; any invalid active target makes the forward loss infinite and zeroes that position's backward cotangent. K is padded to a whole number of chunks when necessary, and a validity mask zeroes padded samples. The largest teacher-specific live array is [N,8,D]. A naïve [N,K,D] tensor and the even larger [N,K,V] comparison are explicitly absent. The softmax makes the final output-table gradient dense regardless of sparse teacher corrections.

The K>1 implementation was refined through three rejected physical paths—dense K-by-vocabulary comparisons, a broad scatter formulation, and larger gathered target materializations—before the chunk-eight sparse correction above. These were implementation changes only; unit tests checked the same loss and gradients against dense reference formulas.

Reconstruction instructions

The following is the durable specification. The unmerged research branch is useful for audit, but none of these steps require merging it into the baseline.

  1. Fork the dense recipe. Copy the reference trainer and the three complete YAML files. Preserve all dense behavior. Add only the arguments, metadata, index loader, host query, teacher sharding, and weighted output loss described above. Keep a separately compiled b=0 branch that calls the original loss and never opens the index.
  2. Prepare ngram. Clone upstream revision 2a73b5ffbe852718dbd4e01ee6abafeb1628c5a7. Add a C++ engine method accepting equally shaped 2-D context/target arrays, K, max length, optional reset token, seed, and output buffers [rows,cols,K] plus three [rows,cols] statistic buffers. Implement the exact segment, search, count, backoff, rejection, and per-position RNG algorithm in this report. Expose it through the type-erased facade, Cython engine, and Python InfiniGram.infgram_loo_sample_k_batch. Retain a K=1 wrapper. Release the GIL around the C++ call and make arrays contiguous in the index token dtype.
  3. Build the index. Validate all manifest file sizes/hashes. Call ngram.build_index with LLMC input, u16 tokens, doc_sep_token=50256, insert_sep=False, shard size 4,000,000,000, 240 CPU workers, 300 GiB memory budget, GPT-2 tokenizer metadata, resume enabled. Afterward require ingest, sa.0000, and sa.0001 completion and write the attestation fields/hashes listed below.
  4. Add the weighted tiled primitive. Give it hidden, output table, primary [..] IDs, teacher [..,K] IDs, a, b, semantic V, tile size, and compute dtype. Implement the forward and custom VJP exactly as in the preceding section, including semantic masking, invalid-target behavior, K=1 compatibility, chunk size eight, padding mask, FP32 accumulation, and mean reduction.
  5. Query inside each timed training step. Query host-local x/y before device placement with seed infinigram_step_seed(run_seed, step_index, jax.process_index()). Convert IDs to contiguous int32, accumulate diagnostics, place with P("data",None,None), and pass them to ordinary or diagnostic JIT. Keep query time inside synchronized train_seconds.
  6. Keep validation pure. The evaluation executable accepts only params/x/y and calls ground-truth tiled CE. Do not report mixed-objective training loss as language-model validation.
  7. Test before TPU use. Compare losses and gradients for K=1 and K>1 with a dense softmax formula, include repeated target IDs, non-divisible storage vocab, semantic padding, invalid IDs, zero coefficient cases, BF16/FP32, JIT, and K-prefix behavior. On the ngram side compare adjusted counts and samples with a brute-force corpus, boundaries, shard tails, empty-backoff cases, empirical frequencies, determinism, and K=1/K-prefix compatibility.
