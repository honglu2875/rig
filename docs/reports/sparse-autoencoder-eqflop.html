Sparse capacity at a fixed algorithmic budget

An overcomplete TopK-ReLU MLP improves validation loss when dictionary width, retained width, transformer depth, and schedule length are balanced against the same 221 PFLOP contraction budget. The kernel is not yet practical; the algorithmic signal is.

The result

A wide dictionary with moderate activity wins

The best treatment stores H=16D features but retains only K=D per token. At twelve layers it reaches 3.910170 validation loss, compared with 4.000445 for the twelve-layer, 4× GELU reference. That is 0.090275 nats, or 8.63% perplexity, at essentially identical algorithmic training compute.

The pattern is more useful than the winning cell. All H=16D treatments with K∈{D,2D,4D} beat dense by 0.070–0.090 nats, and H=8D with K∈{D,2D} improves by about 0.064–0.066. Very aggressive K=D/4 sparsity gives much of that back. Meanwhile H=4D,K=4D is an exact dense-ReLU control and is 0.0165 nats worse than the GELU reference, so this is not a generic ReLU benefit.

The compute contract

Score every feature; backpropagate only through the selected path

Forward

Exact TopK first computes all H feature scores. Only the selected K decoder rows are contracted into the block output.

score: x W_up = 2 D H decode: a W_down[i] = 2 K D ────────────────────────── forward total = 2 D H + 2 K D

Backward

There are four active-width contractions: decoder-row gradient, retained-value gradient, selected encoder-column gradient, and the encoder contribution to dX.

dW_down = 2 K D da = 2 K D dW_up = 2 K D dX = 2 K D ────────────────── backward = 8 K D
Training MLP cost: 2DH + 10KD. The ordinary 4× dense MLP costs 48D²: 16D² forward plus 32D² backward. This makes H=4D,K=4D the equal-cost dense-ReLU control.

The rest of the transformer is traced normally. At the sparse-MLP boundary, the physical gathered program is assigned the declared contraction cost above. TopK sorting, gathers, scatters, padding, memory traffic, bias and activation elementwise operations, and dense AdamW moment updates are outside this matrix-FLOP contract.

This accounting is intentionally honest about the encoder: exact TopK cannot skip xW_up columns without a separate approximate router. What it idealizes is the selected decoder and backward path. That is the right abstraction for asking whether the algorithm deserves a better kernel, but not for claiming current-device speed.

Building the ladder

Depth is the integer lever; steps close the remainder

For fixed width, context, and sparse coordinate, full-model FLOPs per token are affine in layer count. Two short traces identify the non-layer cost A and per-layer cost B; the real-valued depth that matches dense is rounded to the nearest layer. The remaining mismatch is corrected with whole optimizer steps.

F(L; H,K) = A + B(H,K)L B = F(2) − F(1) A = F(1) − B L* = (F_dense − A) / B L = round(L*) C_dense = 2,286 × 131,072 × 737,673,984 = 221,029,692,528,918,528 FLOPs steps(H,K) = round(C_dense / (131,072 × F(L;H,K)))

Cells are transformer layers / optimizer steps. Lower retained width can fund another block; larger stored width still raises cost because all feature scores are computed.

The adjustment is full-model rather than MLP-only. Attention and vocabulary costs remain in every trace, so “halve active MLP width, double depth” would generally be wrong. Integer depth also changes stored parameters. These runs span 59.92M–107.76M parameters and 2.6979–5.0007 tokens per stored parameter even though total training FLOPs are fixed.

Accordingly, the arms are explicit-step cosine schedules, not fixed-TPP experiments. The recipe reanchors duration-dependent multipliers at m_D=1; it does not pretend that their intentionally different token horizons form a Complete(d)P duration ladder.

Interpretation

Promising algorithm, unresolved system

What the study says

Stored feature capacity can be useful without activating all of it. The broad gains around H=16D and K=D–2D justify testing the idea at larger widths once a viable primitive exists. A local 101-step trajectory check at 25%, 50%, and 75% of the common budget also favors H=16D,K=D; the endpoint is not a final-step fluctuation.

What it does not say

One seed cannot resolve the 0.0094-nat gap between the best two cells or estimate a stable effect. LR was not retuned per geometry, and varying depth changes representation composition. Larger-model transfer remains entirely untested.

The current TPU kernel is not scalable. The gathered sparse treatments run roughly 5–57× slower than the dense anchor across this grid; the best-quality cell is about 19× slower. Exact selection and indirect row updates are dominated by gathers, memory traffic, padding, and launch/latency costs that the contraction formula intentionally does not charge. A tested Pallas TensorCore decoder was slower still because this v4 path has no efficient indirect sparse-row DMA.

That is a systems limitation, not a reason to rewrite the endpoint as negative. The appropriate conclusion is conditional: the algorithm buys quality at a fixed ideal sparse-contraction budget, so its value now depends on finding an accelerator mapping that approaches that budget.
